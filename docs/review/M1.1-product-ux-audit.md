## 1. 当前产品定位判断

**它现在是什么：** 一个**组织控制平面（Organization Control Plane）的开发者控制台**，而不是一个面向使用者的 "AI Company" 产品。

- 数据链路是真的：页面数据全部来自真实后端（`[NET]` 仅见 `GET /api/snapshot` + 当前页端点，无 mock、无本地假数据），控制按钮真的调用 `POST /api/command`（`apps/web/src/App.tsx:100-108` → `apps/api/src/api-adapter.ts:12`）。
- 但产品层缺三件事：
  1. **运行**：不会自己往前走（见问题 P0-1），用户无法让组织"动起来"。
  2. **创造**：全站 `input/select/textarea = 0` `[DOM]`，不能创建任务、工作流、消息、审批。
  3. **解释**：事件是裸字段表，没有人类可读的"组织里发生了什么"。
- 定位偏差的证据：侧栏写着 `Backend as source of truth`（`App.tsx:138`），但页面同时用 `LIVE` 这种面向用户的措辞、却把 `failureCode schema_violation`、`occurredAtSim`、`HTTP 500: empty body` 等技术信息直接摆给用户 —— 这是**控制台与产品两种定位的混合**。

**结论：** 作为"控制平面自检工具"可用（6/10）；作为"AI 公司产品"不可用（见第 2 节）。

## 4. 最严重的 10 个问题

1. **[P0] 组织不工作**：所有 agent 周期 `schema_violation` 失败（根因 `apps/api/src/composition.ts:29`），动作数恒为 0 → 产品核心承诺（AI 员工产出）完全落空。
2. **[P0] 仿真不会自己运行**：无 auto-tick、UI 不调用 `/api/tick`、无轮询，`Resume` 后什么都不会发生（`RT-1/RT-2`）。
3. **[P0] 状态撒谎**：断开后端后 UI 仍显示 `LIVE` + 陈旧 `Tick 22`；`Running` 与实际行为矛盾（`G-1`、`O-2`）。
4. **[P0] 没有任何创建入口**：全站 0 个输入控件，任务/工作流/消息/审批都无法创建（`T-1`）。
5. **[P0] 工作流永远无法启动**：控制命令缺 Start/Run（`types.ts:49-53`），Workflows 页永远空（`W-1`）。
6. **[P0] 审批永远不可达**：无 authority 阈值 → 无 `NEEDS_APPROVAL`，Approve/Reject 按钮从不出现（`AP-1/AP-2`，按钮交互**无法验证**）。
7. **[P1] 无路由、无 URL 状态**：不可深链/书签/前进后退（`G-4`）。
8. **[P1] 事件流不可解释 + 被时钟噪声淹没**：约半数事件是 `System.SimClockTicked`，其余是裸类型名（`E-1/E-2`）。
9. **[P1] 响应式崩坏**：1024/1280 表格溢出、390px 页面横滚 + 按钮压标题 + 列不可达（`G-10/G-11/G-12`）。
10. **[P1] 无成功反馈 + 无持久化提示**：命令成功静默、重启即丢数据且无提示（`G-3/G-5`）。

## 7. 应隐藏到 Diagnostics 的技术信息

以下内容目前直接暴露给普通用户，应移入独立的 **Diagnostics / 高级视图**（保留可复制、可跳转）：

- 裸字段名表头：`ASSIGNEEMPLOYEEID`、`CURRENTTASKID`、`OCCURREDATSIM`、`SUBJECTID`、`ACTORID`、`STAGEID`、`BLOCKEDREASON`、`ESCALATETO`、`ATTEMPT`（`App.tsx:32-41`）。
- 裸枚举值：`defined`、`idle`、`false`、`partial_failure`、`NEEDS_APPROVAL`。
- HTTP 层错误原文：`GET /api/snapshot failed with HTTP 500: empty body`、`409 tick is unavailable`。
- 失败码与技术事件：`failureCode=schema_violation`、`outcome=failed`、`Control.CommandRejected`。
- 仿真机器细节：`occurredAtSim`、`sim time`、`queueDepth`、`tickDuration`、`commandId/auditId/eventId`。
- Runtime 页右侧整包 **raw JSON 面板**（改为折叠的"开发者"抽屉）。
- 侧栏口号 `Backend as source of truth`（开发者语言，应移入 About/Diagnostics）。
- `LIVE` 这种含糊的连接/运行混写状态（应拆成"已连接 / 运行中"两个可解释状态）。

## 8. 推荐信息架构

顶层形态：**顶栏（组织 + 运行状态 + 运行控制）+ 分组侧栏 + 详情抽屉/详情页**。

```
顶栏   组织名 · 连接状态(● 已连接/离线 + 最近同步) · ▶/⏸/⏭ 运行控制 · 速度 · tick 徽标

侧栏
├ Company（组织）
│   ├ Overview          组织总览（首页）
│   ├ Agents            员工名册 → /agents/:id（身份/记忆/目标/技能/最近产出）
│   └ Structure         汇报线、权限、角色（新增）
├ Work（工作）
│   ├ Tasks             任务（含创建入口 + 看板/列表）
│   ├ Workflows         工作流实例 + 阶段进度 + 启动入口
│   └ Approvals         待我审批收件箱（Approve/Reject 可点）
├ Activity（活动）
│   ├ Timeline          合并 Events + Communications，人类可读、可筛选
│   └ Audit             命令/权限/变更痕迹（暴露现有 /api/audits）
└ Diagnostics（诊断，二级/折叠）
    ├ Raw Events（含 occurredAtSim / failureCode）
    ├ Simulation State（raw JSON）
    └ Errors & Retries
```

原则：
- 面向用户的页面只说**业务语言**；机器字段只在 Diagnostics 出现。
- Approvals 同时出现在顶栏徽标（"3 待你决策"）——审批是决策入口，不是数据库表。
- 事件与通讯合并为 Timeline（两者本质都是"组织里发生了什么"），原始事件表降级到 Diagnostics。

## 9. 推荐首页结构（Overview 重建）

从上到下：

1. **状态条（真值）**：连接状态（已连接/离线 + 最近同步时间）、运行状态（已暂停/运行中）、`Tick N`（次要）、速度控制（▶ 运行 / ⏸ 暂停 / ⏭ 单步）。
2. **组织一句话**：`Future AI Lab 现在…` —— 3 名员工在线，2 个任务进行中，1 个工作流在"技术评审"阶段，0 项待你决策。（由 snapshot 派生，字段口径统一。）
3. **需要你介入**（无则折叠）：待审批、被阻塞任务、失败的 agent 周期（带"重试/改派"）。
4. **员工在做什么**：员工卡片（姓名/职称/状态/当前任务/最近一条产出），点击进详情。
5. **工作进展**：工作流阶段进度条 + 任务看板（Backlog / In progress / In review / Done）。
6. **最近活动**：Timeline 前 8 条（人类可读），"查看全部"进 Timeline。
7. **空态引导（首次运行）**：`还没有任务` → 按钮「创建第一个任务」「运行一个 tick」+ 3 步引导。

## 10. 推荐核心用户流程

1. **F1 第一眼（30 秒）**：打开 → 看懂"谁在做什么、卡在哪、我需要决策什么"。
2. **F2 让组织动起来**：点 ▶ 运行（或 ⏭ 单步）→ 状态真实推进 → Timeline 出现可读事件。
3. **F3 交办工作**：新建任务 → 选择员工/自动派单 → 运行 → 观察执行 → 完成/复盘。
4. **F4 走一个工作流**：启动预置工作流 → 看阶段推进 → 触发审批 → Approvals 批准/驳回 → 继续到完成。
5. **F5 处理异常**：Timeline 报"John 的周期失败" → 详情看原因 → 重试 / 改派 / 暂停该员工。
6. **F6 解释与追溯**：Timeline 点开一条决策 → 看依据与相关记忆 → Audit 追到谁下的命令、什么权限。

当前产品中 F2（部分，仅手动 Step）、F5（仅能看到失败）、F6（Audit 缺页面）不可达或半可达；F1/F3/F4 完全不可达。

## M1.2 Product Improvement Plan

> 只排优先级与范围，不在本阶段实现。目标：先让产品**不撒谎、能跑通一条闭环**，再补信息架构与打磨。

### P0 — 让产品真实可运行（先解决"假"和"空"）

1. **运行真实化**：接通自动推进（或明确显示"手动模式"，只有手动 Step 时才显示 `Running`）；`LIVE` 仅在"已连接 + 运行中"时显示，断连立即全局横幅 + 自动重连。
2. **修复 agent 周期失败**：替换/参数化 `composition.ts:29` 的空步骤 mock，使 agent 能产出合法 steps，组织能真正完成任务。
3. **最小创建闭环**：Tasks 页新增"创建任务"表单（标题/描述/指派/优先级）+ 派单反馈。
4. **成功反馈**：命令成功给出可见确认（toast / 行内状态），失败保留但技术细节进 Diagnostics。
5. **首页空态引导**：首次运行可一键"创建任务 → 运行一个 tick"，让新用户 1 分钟内看到组织动起来。

### P1 — 打通核心流程与可信度

6. **工作流可启动**：暴露启动命令/预置实例，Workflows 页显示阶段进度与阻塞原因。
7. **审批可达**：为 CEO/角色定义 authority 阈值 → 产生 `NEEDS_APPROVAL` → 收件箱出现 → Approve/Reject 可点 → 结果回执与事件联动。

9. **事件降噪与可读化**：过滤 `System.SimClockTicked`（或折叠为计数）、事件显示人类描述、支持按 agent/类型筛选、失败事件高亮 + 重试入口。
10. **响应式修复**：1024/1280 表格溢出、390px 布局（汉堡侧栏、按钮不压标题、表格横向滚动而非裁切）。
11. **持久化或显式声明**：要么落库，要么在 UI 明示"内存态，重启即重置"。
12. **实时刷新**：轻量轮询或 SSE，让 `Tick/状态` 不必手动 Refresh。
