# M1.3 Agent Lifecycle Management — Verification Report

> Milestone: **M1.3 — Agent Lifecycle Management**
> The organization can now **create / read / archive agents** through the real chain
> `console → HTTP API → Runtime → Organization → EventStore → Audit`, with two new facts
> (`AGENT_CREATED` / `AGENT_ARCHIVED`), archive-as-status instead of deletion, and a
> fail-closed "no archive while the agent owns running work" rule.

Gates: `pnpm lint` · `pnpm typecheck` · `pnpm test` · `pnpm architecture:check` · `pnpm build` ·
`pnpm test:e2e` — **all PASS** (§5).

**Verdict: M1.3 = PASS** (§7).

## 3. API Reference

### 3.1 Commands (all through `POST /api/command`)

`Agent.Create` — target `{ targetType: 'organization', targetId: <companyId> }`:

```jsonc
{
  "commandId": "ui-…",                       // idempotency key
  "commandType": "Agent.Create",
  "actor": { "operatorId": "ceo-alex", "displayName": "Alex", "positionId": "ceo", "kind": "human" },
  "target": { "targetType": "organization", "targetId": "future-ai-lab" },
  "reason": "…",                             // mandatory, audited
  "correlationId": "ui-…", "causationId": null, "createdAtSim": 0,
  "employeeId": "qa-priya",                  // stable id (letters/digits/._-)
  "name": "Priya",
  "positionId": "qa",                        // must exist in the organization
  "employeeNo": "FAL-004",                   // optional, unique
  "responsibilities": ["test_strategy"],     // required, at least one
  "traits": ["methodical"],                  // optional
  "cognitionProfileId": "tech-task",         // optional; resolved from the template otherwise
  "templateEmployeeId": "engineer-mike"      // optional; capabilities/memory/tool policy source
}
```

`Agent.Archive` — target `{ targetType: 'agent', targetId: <employeeId> }`, no extra payload.

Outcomes use the existing `ControlOutcome` contract. Refusal codes added by M1.3:

| Situation | HTTP body | Code |
|---|---|---|
| employee id or employee number already taken | `status: rejected` | `CONFLICT` |
| unknown position | `status: rejected` | `INVALID_TARGET` |
| no responsibilities / malformed id / over-long field | `status: rejected` | `INVALID_COMMAND` |
| unknown cognition profile or template agent | `status: rejected` | `INVALID_COMMAND` |
| unknown agent (archive) | `status: rejected` | `NOT_FOUND` |
| archive while a non-terminal task is owned | `status: rejected`, reason lists the task ids | `CONFLICT` |
| archive an already archived agent | `status: rejected` | `CONFLICT` |
| archive the identity the operator acts as | `status: rejected` | `FORBIDDEN` |
| actor paused/archived, or runtime instantiation fails | `status: rejected` | `INVALID_STATE` |
| operator lacks the `ControlAgent` grant (domain `org`) | `status: rejected` | `UNAUTHORIZED` |

### 3.2 Reads

| Endpoint | Purpose | Notes |
|---|---|---|
| `GET /api/agents` | roster list | each row now carries `lifecycle: 'active' \| 'archived'` (plus the raw `status`, e.g. `offboarded`) |
| `GET /api/agents/:id` | **new** — read one agent | `200` with the `AgentSummary`, `404 {"error":"unknown agent …"}` otherwise; archived agents are returned too |
| `GET /api/snapshot` | organization chart | a created agent appears in `agents` **and** in `positions[].employeeIds` |
| `GET /api/events` | event stream | `Control.AgentCreated` / `Control.AgentArchived` |
| `GET /api/audits` | audit trail | one row per command: `actionType`, `reason`, `verdict`, `eventIds` |

### 3.3 Events

| Event type | Constant | Subject | Payload (abridged) |
|---|---|---|---|
| `Control.AgentCreated` | `AGENT_CREATED` | `employee:<new id>` | `commandId`, `operatorId`, `reason`, `agentId`, `name`, `positionId`, `employeeNo`, `responsibilities[]`, `traits[]`, `cognitionProfileId`, `templateEmployeeId`, `definitionSource`, `status: 'active'` |
| `Control.AgentArchived` | `AGENT_ARCHIVED` | `employee:<id>` | `commandId`, `operatorId`, `reason`, `agentId`, `status: 'archived'`, `employmentStatus: 'offboarded'` |

Both are registered in the event registry (so `createOrgEvent` validates them) and both appear in
`CONTROL_EVENT_TYPES` / `isControlEvent()`. Naming follows the repository contract
`<Aggregate>.<PastTenseVerb>`; `Agent` is **not** an aggregate in `event-system/taxonomy.ts`, and
adding one would be a new event namespace — the milestone reuses `Control.*` on purpose.

## 6. Constraints and Locked Decisions Honored

* **No new architecture**: no new package, no new state machine, no new permission/authority
  mechanism, no parallel event store. `Agent.Create` / `Agent.Archive` reuse the existing
  `ControlCommand` envelope, `AuthzService.can()`, `event-store.append` and the audit port.
* **Control plane purity** (`control-boundaries.test.ts`, `dependency-cruiser control-plane-pure`):
  the control plane still never imports `agent-runtime` / `agent-definition` / `llm-gateway` /
  `persistence`; agent instantiation happens in the Runtime (`apps/kernel`).
* **The Runtime owns the roster change**: `organization.employees` is only written by
  `Simulation.createAgent` / `archiveAgent`, reached through `ControlSimulationPort` — the same
  bridge `Agent.Pause` already used.
* **Archive ≠ delete**: `employees.status = 'offboarded'`, `lifecycle = 'archived'`; events,
  audit, definition and identity remain addressable and readable.
* **No hidden work loss**: archive is refused while any non-terminal task is owned by the agent,
  and assigning to a vacated position leaves the task waiting rather than re-targeting a retired
  agent.
* **Explainability**: every command leaves one audit row (actor, reason, verdict, event ids) and
  one event; refusals are recorded as `Control.CommandRejected` plus a rejected audit row.

## 7. Known Limitations and Follow-ups

* **Durable roster** (resolved while finishing this milestone): the kernel always accepted an
  injected `EventStore`, and the API composition now supplies a **file-backed** one
  (`MAOEH_EVENT_LOG`, default `.maoeh/state/future-ai-lab/events.jsonl`; `memory`/`off` = isolated
  in-memory run). Because `Agent.Create` / `Agent.Archive` are facts on that log, a restart replays
  them: the created agent, its position and its reporting line come back, and an archived agent
  stays archived. Pinned by `tests/integration/agent-create-restart.test.ts` (both modes). The
  earlier "in-memory roster" caveat therefore no longer applies to the console; the E2E and the
  integration tests run in isolated-log mode so they never touch the operator's company.
* **Runtime state must stay out of tooling**: `.maoeh/` is generated data (it is in `.gitignore`),
  so it is now also ignored by ESLint — without that, `pnpm lint` races the live runtime and can
  fail on `ENOENT: scandir '.maoeh'` while the log directory is recreated.
* **Position slots are not vacated in the domain model**: the archived employee keeps its
  `positionId`, so `GET /api/positions` still lists them as staff. Work routing is already correct
  (the task-system skips non-executable holders), but a future milestone should model
  `positions.status = open` and the delegation/acting mechanism of 04-agent-lifecycle §4.6.
* **Channel membership is not retroactive**: a newly created agent is not added to channels that
  were opened before it existed (there is no channel-membership event yet), so it can receive
  tasks and instructions but is not a member of the company channel.
* **Create derives capabilities from a template**: `capabilities`, `memoryPolicy` and `toolPolicy`
  come from the chosen template (position SOP); only identity, mandate, traits, position and
  cognition profile are operator-authored. A future "agent definition" authoring surface belongs
  to the M1.3+ roadmap, not to this milestone.
* **Self-archive guard**: the console operator acts as `ceo-alex`, so that one row cannot be
  archived from the UI (the API answers `FORBIDDEN` with a reason). This is deliberate
  (self-lockout prevention), not a UI bug.
