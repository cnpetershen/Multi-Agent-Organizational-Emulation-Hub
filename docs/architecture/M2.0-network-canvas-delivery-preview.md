# M2.0 · 协同网络画布与交付物预览

> 状态：已接受（2026 · M2.0）
> 关联：A1–A5、ADR-003（LLM 只提议）、ADR-005（事件溯源 + CQRS）、M1.4（交付物）、M1.6（preview）、M1.8（改派画布）

## 目标

把公司已有的三个读模型——组织、工作流实例、已交付任务——放进**同一张实时画布**，让
所有者一眼看到「谁在做什么、哪条分支在跑、交出了什么」；同时补齐两种最常见的交付物预览：

1. **游戏**：交付记录里 `index.html` 形式提交的单文件游戏，必须真的能在控制台里运行；
2. **文档**：Markdown / HTML 文档必须按文档呈现，而不是把正文当纯文本打印。

画布引入 3D 全息核心作为**展示点缀**，不是数据源：关掉动效、低端设备、屏幕阅读器下，
所有事实仍然由同一页的标题、指标、检查器和交付剧场以文字给出。

## 决策

### 1. Network 是投影，不是新领域

- 页面只读 `snapshot`、`/api/workflows`、`/api/tasks/:id`、`/api/llm` 与 `/api/preview`，
  不新增事件、命令、表或持久化状态。
- 布局模型在纯函数 `apps/web/src/network.ts` 中：
  - 左侧一列：Agent（按部门聚合）；
  - 右侧一列：工作流分支（默认 7 条；超过 8 条时切两列并缩小卡片）；
  - 底部一行：最近交付物（默认 4，展开 5）；
  - 边只有三种真实关系：`reports`（汇报线）、`runs`（分支发起人）、`delivers`（交付来源）。
- 每条分支只画**一个责任人**的 `runs` 边；全部涉及席位保留在检查器里。把每个席位都画成
  边会让画布变成不可读的交叉束。
- 图默认只展示摘要，`hiddenWorkflows` 明确告诉页面被折叠了多少条；「显示全部」是布局
  变化，不是数据过滤。

### 2. 3D 是视觉锚点，也是既有点选路径的指针快捷方式

3D 核心已经从「一小圈轨道环」升级为整页的视觉锚点；它**没有**变成新的数据源，
只是把已有的 Agent 选择做成了可悬停、可点选的指针入口：

- `components/HoloCore.tsx` 由四层组成：
  - CSS `transform-style: preserve-3d` 的**线框球体**：6 条经线 + 3 条纬线，在
    `rotateX(-12deg)` 下绕 Y 轴自转（真实透视，无 WebGL 上下文）；
  - 三条不同轴向的轨道环、赤道雷达扫掠面、投影底座与光锥；
  - 2D canvas 的**深度投影粒子 + Agent 信标**：粒子分布在球壳内，按 `1 / (1 + z)`
    投影；6 个 Agent 信标沿倾斜轨道运行，靠近观察者的更大更亮并压过远端的信标；
  - 中心公司核：`translateZ` 抬到球体前方，避免侧对镜头的经线正好从公司首字母上穿过。
- 视觉尺寸由 `.network-page` 的 `--core-size` 控制（默认 400px；≤1180px 300px；
  ≤820px 270px；≤520px 210px）。组件内部全部用百分比定位，缩放不改变结构。
- 画布节点也分层：Agent `translateZ(34px)`、工作流 `20px`、交付 `8px`。指针倾斜从
  ±5°/±4° 提到 ±9°/±7°，倾斜时产生真实视差；边仍在 `z=0`，端点落在卡片内部。
- **悬停暂停 + 信标快捷方式**：鼠标进入全息体的圆形悬停面（`.holo-hover`）后，CSS 动画与
  canvas 时钟一起冻结，虚线悬停环出现，移动中的信标停在原地。每个信标在 DOM 里有一个透明
  按钮（`.holo-beacon-hit`）；点击它只调用页面已有的 `select(agentId)`，右侧检查器显示该
  员工的实时状态，与点左侧 Agent 卡片是同一条路径。点击全息体空白处回到实时编排面板。
- **可访问性边界不变**：组件 `aria-hidden`；信标按钮 `tabIndex={-1}`，键盘/读屏用户走左侧
  Agent 卡片。页面「动效开/关」与 `prefers-reduced-motion` 会暂停全部 CSS 动画，并让 canvas
  只画一帧静态粒子。同一事实仍由标题、指标、检查器和交付剧场以文字给出。
- 全息体是交互面，拖拽平移从它以外的画布区域开始；圆形悬停面四角仍可穿透。公司核与标题
  保持可点，点击都回到实时编排面板。
- 鼠标视差与缩放只是 CSS 变量，不改布局坐标；重置视图是纯 UI 操作。canvas 使用布局坐标
  计算信标，145% 世界缩放时信标仍与轨道环对齐。

### 3. 预览补全：从交付数据恢复文件

**问题**：真实模型有时用 `{ "index.html": "<!doctype html>…" }` 交付单文件游戏，而不是
`{ files: [{ path, content }] }`。预览配方只读 `data.files`，于是 tic-tac-toe / snake 这类
真实、可玩的交付被报告为「the delivery carries no files」，预览根本不可用。

**决策**：`preview-plan.ts` 新增纯函数 `deliveryFilesFromData(data)`，按优先级恢复：

1. `data.files[]`（原有契约）；
2. 形如文件路径的 data key（`index.html`、`client/app.js`）；
3. `data.entrypoint` + `data.content`；
4. 没有 entrypoint 但 `content` 是 HTML 时命名为 `index.html`。

路径先经 `normalizePath`，绝对路径 / `../` / 盘符一律丢弃；重复路径保留第一条更丰富的
记录。`composition.ts` 的 `filesOfTask` 改用该函数，预览运行时的行为不变。

### 4. 文档预览：AST 而不是 innerHTML

- `markdown.ts` 是**解析器**：把交付的 Markdown 解析成 `MarkdownBlock[]`（标题、段落、
  列表、代码块、引用、分隔线、表格）和 `InlineNode[]`（文本、代码、粗体、斜体、链接）。
- `document-preview.ts` 选择正文：优先最大的 `.md` 文件，其次单文件 `content`，再次
  HTML 文档 / 纯文本；标题优先第一个 ATX 标题，其次 `data.name` / 任务标题。
- `components/DocumentPreview.tsx` 只把 AST 映射成 React 元素：
  - 链接只允许 `http(s)` / `mailto` / 片段 / 相对路径，`javascript:` 与 `data:` 降级为文本；
  - HTML 文档放进 `sandbox=""` 的 `srcDoc` iframe，脚本禁用；
  - 提供「预览 / 源码」切换，源码仍是转义后的 `<pre>`。
- `/results/:taskId` 的 `document` 分支改为渲染该组件，并给可玩交付显示 `Playable game`
  徽章；页面其余七个区块、下载、工作历程、角色贡献均不变。

### 5. 交付剧场

- `network.ts` 的 `showcaseDeliveries(tasks, limit)` 做**展示选择**：优先最新的游戏型标题、
  最新的文档型标题，再用最新完成任务填满。它只选出候选，不判定类型；卡片自己读取
  `TaskRecord` 后再用 `isPlayableGame` / `deliverableKind` 决定形态。
- 游戏卡在页面内打开 `PreviewDialog`：`usePreview` 自动启动真实预览，iframe 指向运行时
  分配的端口；关闭时停止预览并释放端口。
- 文档卡渲染紧凑版 `DocumentPreview`，主按钮进入交付中心阅读完整文档。

## 复审触发条件

- Network 需要展示**跨公司**或多公司网络（当前只投影当前激活公司）；
- 布局需要拖拽持久化 / 用户自定义节点位置（当前是确定性布局，刷新即复位）；
- 3D 从点缀升级为承载数据（例如节点空间位置即组织距离），或成为**唯一**的选择入口
  （当前信标只是 Agent 卡片的指针快捷方式）——那时需要重新论证可读性、可访问性与可测试性，
  不能只加视觉；
- 文档预览需要执行脚本或内联 iframe 同源（当前 `sandbox=""` 是安全边界，不得静默放宽）；
- 预览配方需要识别更多文件形态（压缩包、多文件入口、构建产物），应扩展
  `deliveryFilesFromData` 的显式规则并补单测，而不是在 `PreviewRuntime` 里加产品常量。
