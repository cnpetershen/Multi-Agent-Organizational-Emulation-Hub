# MAOEH 省赛冲刺计划（PROVINCIAL_FIRST_PLAN）

> 目标：省赛一等奖。本计划以 2026-11-14 的真实仓库状态与真实运行数据为基线（见 `TONIGHT_AUDIT.md`），只承诺**能做到并有证据**的事。
> 时间口径：以省赛材料提交日为 D0 倒排，共 4 周；若通知日期变化，按同样比例压缩，不改变优先级顺序。

---

## 1. 我们靠什么赢

省赛评委通常按四件事打分：**创新性、技术难度、完成度、应用价值**，再叠加**工程规范**与**现场表达**。MAOEH 的得分结构应该是：

| 维度 | 我们的主张 | 必须拿出的证据 |
| --- | --- | --- |
| 创新性 | 不是"多 Agent 聊天"，而是**可回放的组织仿真**：组织图、岗位权限、事件日志、认知循环、控制面是同一个运行时 | 一次真实协作的事件因果链；`/api/snapshot` 与事件日志同源 |
| 技术难度 | 事件溯源 + 权限/权威引擎 + 能力路由 + 认知执行器 + 预览运行时 + 控制面，全部有边界测试 | 53 个 typecheck 任务、1254 个测试、架构依赖规则 |
| 完成度 | 端到端可运行：从"人类下指令"到"交付物可预览/可下载" | 真实 DeepSeek 生成的四平台文案；真实 Python/Node 交付物预览 |
| 应用价值 | 两个可讲清的样板：**一鱼多吃**（内容团队）与**赛博沙盘**（多角色对抗评审） | 真实 LLM 输出、真实多角色会话（待建）、导出与审核闭环 |
| 工程规范 | 事件不可变、权限不绕过、失败可解释、测试不放水 | 审计文档里的失败归因；未删除任何既有测试 |

**一句话定位**：MAOEH 是一个"能被审计的 AI 公司"——每个 AI 员工做什么、为什么做、谁批准、结果如何，都能从一条事件链里还原。

## 2. 现状盘点（照实说）

### 已经真实成立

1. **组织与权限**：7 个 AI 员工、15 个岗位、5 个部门；岗位权威等级与决策域真实参与授权；拒绝路径有日志。
2. **认知执行链**：唤醒 → 认知 → 计划 → 执行 → 事件 → 状态回写，全链路可追踪，单周期最多 8 步、有预算上限与重试白名单。
3. **真实双 Agent 协作**：架构师遇到设计问题 → 主动发消息请教工程师 → 工程师给方案 → 架构师采纳并提交 → 任务完成，事件因果链完整（隔离实例真实 DeepSeek 跑通）。
4. **真实 LLM 多平台生成**：一份素材，四个平台各一次模型调用，输出格式与长度确实不同（长度 341–821 字，两两 4-gram 重合 ≤ 0.098），页面明确标注 `LLM · deepseek-flash`。
5. **交付物预览运行时**：交付的 Python/Node 项目会被复制到隔离目录、真实起子进程、动态端口、真实 URL 访问。
6. **可观测与控制**：`/api/snapshot`、`/api/communications`、`/api/events`、`/api/runtime`、`/api/llm`；控制面支持暂停/恢复/指示/审批/注入任务/重分配。

### 仍然薄弱（省赛前必须处理）

| 问题 | 影响 | 处理方式 |
| --- | --- | --- |
| 赛博沙盘已重建，但只验证了 1 轮真实会话 | 多轮稳定性与并发未证 | W2 做 ≥3 轮压力验证 + 会话队列（P1） |
| 7 个 Agent 认知画像全部相同 | "多角色"的说服力弱 | 至少给 4 类角色做异构画像与工具策略（P1） |
| `RequestCollaboration` 不在动作空间 | "协商"只能靠消息，不能靠协作请求 | 加入 `ACTIONS` 并验证模型会用（P1） |
| 交付断言宽松（`implementation_report` 也能完成实现任务） | 可能出现"完成但没产品" | 收紧实现类交付必须有可运行文件（P0） |
| 图片/音频/视频生成缺失 | 一鱼多吃只能讲图文 | 明确列为边界，或接一条真实图像链路（P2） |
| 频道成员不随招聘更新 | 新员工进不了公司频道 | 设计 `Channel.MembersChanged` 事件（P2） |
| 前端任务时间线缺失 | 评委看不到协作过程 | 协作剧场时间线视图（P1） |

## 3. 三条主线与里程碑

### 主线 A：组织仿真内核（守住技术难度与工程规范）

**A1（W1）事件与状态的"同源"证明**
- 产出一份《同一家公司：事件日志 → 状态快照》对照材料，任选 3 个任务、1 个工作流、2 条消息，逐条对应。
- 验收：脚本可复现（读日志 → 重放 → 与 `/api/snapshot` 一致）。
- 风险：低。

**A2（W2）认知异构**
- 为 4 类角色（战略 / 技术 / 交付 / 质量）设计不同的推理-规划-反思画像与工具策略，并让同一任务在不同角色下产生**可比较的差异**（计划长度、是否请求协作、是否升级）。
- 验收：同一输入、不同角色的计划差异有数据；不是"改一段提示词"就算完。
- 风险：中（模型行为不稳定，需要多次采样）。

**A3（W3）质量门禁固化**
- 把 typecheck / lint / architecture / unit / integration / e2e 固化为一条命令 + 一份报告；对已知 flaky（预览子进程超时）做隔离或重试策略，**不放宽断言**。
- 验收：CI 或本地一键跑完，结果可贴进材料。

### 主线 B：多 Agent 协作（守住创新性）

**B1（W1，已完成）真实消息闭环**
- 现状：单请求-单回复-任务闭环，因果链完整，隔离实跑通过。
- 补强：把验证脚本接入 CI（用小模型或 mock 跑，避免 CI 烧钱）。

**B2（W1）协作请求进入动作空间**
- `RequestCollaboration` 加入 `ACTIONS`，提示词给出契约，真实模型复跑一次，确认它会选。
- 验收：日志出现 `Communication.CollaborationRequested`，且目标 Agent 被唤醒并回应。

**B3（W2）多 Agent 群聊式协作**
- 从"一对一"扩展到"一个频道里 3–4 个 Agent 围绕一个议题发言"，用消息事件驱动，不用定时器造消息。
- 验收：一次 3 人以上、≥6 条消息的会话，transcript 完全由事件日志生成。

**B4（W3）协作剧场**
- Communications 页面按 `correlationId` 聚合成时间线：任务交接、消息、决策、完成。
- 验收：打开页面能看到"谁在什么时候把什么交给了谁，结果如何"。

### 主线 C：两个应用样板（守住应用价值）

**C1（W1，已完成）一鱼多吃真实生成**
- 现状：`/api/studio` + `/api/content/generate`，真实 DeepSeek 四平台生成，provenance 标注，编辑/审核/导出闭环。
- 补强：把"生成 → 修改 → 审核 → 导出"做一次完整录屏；接一条真实图像链路（可选）。

**C2（W2）赛博沙盘：MVP 已完成，剩增强**
- 已完成（2026-11-14 夜）：`/api/sandbox` + `sandbox-session.ts`。4 个真实 Agent（提案/质询/答辩/评审）在独立运行时里逐轮发言，每条发言都是真实 `Communication.MessageSent`，transcript 来自事件日志，评审返回带 `messageId` 的引用式评分，会话可回看。真实 DeepSeek 跑通 1 轮（4 条消息 / 10.6s / 评分 80）。
- 剩余：≥3 轮压力验证、并发会话队列、评分解析失败重试、浏览器端截图与录屏。
- 验收：不再需要人工切换角色；一次完整会话 ≥ 3 轮；评分能指回具体发言；会话可保存、可回看、可导出。

**C3（W3）两个样板共用引擎的证据**
- 同一段代码（通信 + 认知 + 事件）既产出"架构师请教工程师"，也产出"四人对抗质询"。
- 材料里用一张图讲清：**同一引擎，两种应用**。

## 5. 评分点 → 证据 → 演示动作

| 评分点 | 证据 | 现场动作（≤2 分钟） |
| --- | --- | --- |
| 创新性 | 组织图 + 事件日志 + 权限拒绝记录同源 | 点开一个被拒绝的命令，展示"为什么被拒" |
| 技术难度 | 架构边界测试、1254 个测试、预览运行时 | 打开一个真实交付物，点"运行"得到 URL |
| 完成度 | 从指令到交付的完整链路 | 下一条指令，等 Agent 产出交付物 |
| 应用价值 | 一鱼多吃四平台真实文案 | 现场生成一次，指出四平台差异与 provenance |
| 多 Agent | 双 Agent 协作因果链 / 多人质询会话 | 打开 Communications，指出"谁问了谁，谁答复，任务何时完成" |
| 工程规范 | 测试与失败归因报告 | 展示审计文档里的"失败 → 归因 → 修复"记录 |

## 6. 明确不做（scope control）

- 不做"通用聊天机器人"入口。
- 不做多租户/计费/权限后台等运营功能。
- 不为了动画效果替换 2.5s 轮询为 SSE（除非协作剧场确有阻塞）。
- 不在省赛前做数据迁移、事件结构破坏性变更。
- 不接入音视频生成，除非图文链路已经稳定且有剩余时间。

## 7. 风险登记

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 赛博沙盘多轮编排超时/成本高 | 高 | 高 | 限制轮数（3 轮）、限制并发、会话异步化 + 轮询、先做 3 人 |
| 真实模型不稳定（计划不合法） | 中 | 中 | 保留确定性 mock 作为演示兜底，并在页面标注模式 |
| 演示当天网络/额度问题 | 中 | 高 | 提前录制关键链路视频；mock 模式可完整跑通 |
| turbo 缓存导致旧构建上线 | 已发生 | 中 | 演示前 `turbo run build --force` + 校验 dist 关键字 |
| 既有 flaky 测试在评审机器上失败 | 中 | 低 | 隔离/重试策略，材料里说明归因 |
